# figalign

論文のfigureを**実寸で**組む。

Pythonでパネルを描き、Illustratorに持っていって配置する。データとの繋がりはそこで切れる。査読でデータの差し替えを求められると、配置の作業は丸ごと捨てることになる。figalign はこの往復を消す。

```
レイアウト宣言 → ソルバ → 各パネルの実寸(mm) → matplotlibが実寸で描画 → 無変換で貼る
```

後から拡縮しないので、パネル間でフォントサイズと線幅がずれない。

## インストール

このリポジトリのクローンで:

```sh
uv sync
uv run figalign example
```

`uv.lock` をコミットしているので、figure の確認に使ったものと同じバージョンに解決される。これは通常より重要で、理由は後述する。

PDF出力にはextraを足す:

```sh
uv sync --extra pdf
```

cairosvg はシステムの `libcairo` を必要とし、pip はこれを供給できない。macOS なら `brew install cairo`、Debian なら `apt install libcairo2`。root が無い環境 (計算クラスタなど) では、cairo をパッケージとして持つ conda 経路を使う:

```sh
micromamba create -n figalign -c conda-forge python=3.12 matplotlib fastapi uvicorn watchfiles cairosvg
micromamba run -n figalign python -m pip install -e . --no-deps
```

cairo が無くても、合成PDF以外はすべて動く。プレビュー、SVG出力、ライブリロード、そしてパネル単体のPDF (これは matplotlib 自身のPDFバックエンドを通る)。

## 再現性

figure の寸法は `fig.toml` だけの関数ではなく、環境の関数でもある。マージンは `get_tightbbox()` から実測しており、その戻り値は matplotlib が選んだ目盛りの位置と、解決されたフォントに依存する。つまり **matplotlib のバージョンが違うと、同じ宣言から違う寸法の figure が出る**。環境を固定することが出力を守ることなので、lock ファイルは gitignore せずコミットしている。

環境を固定すれば、出力は実行間でバイト単位で一致する。そのために2つの設定が必要で、どちらも既定値ではない。

- `svg.hashsalt` を固定している。さもなければ matplotlib はクリップパスとマーカーの名前を `uuid4()` から作るので、同じ figure が描画ごとに違うファイルになる
- メタデータから日付を落としている (SVGとPDFの両方)

## 動かす

```sh
micromamba run -n figalign figalign example
# -> http://127.0.0.1:8765
```

ブラウザを開かずに書き出すこともできる:

```sh
micromamba run -n figalign figalign example -o figure.pdf
micromamba run -n figalign figalign example -o figure.svg
```

データが計算サーバー上にある場合は、そちらでサーバーを起動して `ssh -L 8765:localhost:8765 <host>` でポート転送すれば、手元のブラウザでプレビューできる。

## figure の書き方

`fig.toml`:

```toml
preset = "nature_double"        # 図幅と文字スタイルはプリセットが持つ

grid = [["a", "a", "b"],        # mosaic文字列 "aab\ncdb" も可
        ["c", "d", "b"]]

row_heights = ["1fr", "0.7fr"]  # fr と mm は混在可。固定長を先に引く
gap = "4mm"

[panels.a]
fn = "panels.py:scatter_main"

[panels.c]
src = "schema.svg"              # 手描き素材をセルに流し込む
```

| キー | 既定 | 内容 |
|---|---|---|
| `preset` | `"default"` | `nature_single` / `nature_double` / `science_*` / `cell_*` / `default` |
| `grid` | 定義順に1行 | 2次元配列または mosaic 文字列。`"."` は空セル |
| `col_widths` `row_heights` | すべて `"1fr"` | `"1fr"` と `"25mm"` を混在可 |
| `gap` `gap_x` `gap_y` | `0` | セル間の間隔 |
| `width` | プリセットの幅 | 総幅の上書き |
| `height` | 未指定 (`1fr` = 40mm) | 総高さ。指定すると fr が残りを按分する |
| `labels` | `true` | a, b, c... の自動採番 |
| `data` | あれば `panels.py:load_data` | データ層の入口 |

`panels.py`:

```python
def load_data():
    """重い読み込みはここ。mtime が変わるまで結果を保持する"""
    return ...

def scatter_main(ax, data, size):
    """figsize は外から注入される。ここで図のサイズを決めない"""
    ax.plot(data["x"], data["y"])
```

## 出力

| URL | 内容 |
|---|---|
| `/` | プレビュー |
| `/ws` | 監視対象ファイルの変更通知 |
| `/api/figure.svg` | grid に従って合成した最終SVG |
| `/api/panel/{name}.svg` | パネル単体 (`?w=88mm&h=46mm`) |
| `/api/figure.pdf` | 成果物。cairosvg で変換 |
| `/api/panel/{name}.pdf` | パネル単体のPDF (`pdf.fonttype = 42`) |
| `/api/stats` | 接続数と描画キャッシュのカウンタ |

2つの形式は同じものを2度出しているのではない。

- **SVG はテキストをテキストのまま保つ。** 軽く、Illustrator で開けるので、プレビュー向きの形式になる (仕様9)
- **PDF は先にテキストをパス化する。** cairosvg がファイルを見る前に matplotlib 側で outline にする。さもないと同じ figure を2つのエンジンがレイアウトすることになり (プレビューは matplotlib、PDFは cairo)、グリフ単位では一致しない。cairo は自分でフォントを解決するので、プリセットのフォントが無いマシンでは黙って代替される。テキストのまま残すには `?text=keep` または `--keep-text` を渡す。ページは約30%小さくなり、選択可能なままになる

ページは宣言した実寸で出る。180×90.31mm の figure なら MediaBox は `0 0 510.23622 255.983244` pt で、PDFをラスタライズすると各軸枠はソルバが置いた位置の1画素以内に収まる。

## 軸枠の整列

パネルを独立に描画すると軸枠が揃わない。枠の外側のマージンはほとんどが目盛りラベルで、その幅がパネルごとに違うからだ。figalign はセルではなく枠を解く (仕様5.2)。

1. 各パネルを一度描いて `ax.get_tightbbox()` と `ax.get_position()` の差を実測する
2. *inner box* (枠そのもの) が同じ列で同じ座標に来るように解く
3. `figsize` と `subplots_adjust` を厳密指定して本描画する

整列は実測が正確であることに依存しない。3番目で枠をソルバの計算位置に打ち込むからだ。実測が決めるのは「周りのラベルに十分な余白を確保できたか」だけである。

この2つは互いに依存する (matplotlib は軸のサイズから目盛り位置を選び、マージンはそのラベルでできている) ため、反復する。普通の figure は2〜3パスで収束する。実測はキャッシュされるので、編集後の再計算は無料。

知っておく価値のある帰結が2つある。

- **`fr` が按分するのは枠であって、セルではない。** `1fr` の2列は目盛りラベルがどうであれ同じ枠幅になる。固定の `"30mm"` も「枠が30mm」を意味する。figure はその周りに育つので、同じ `row_heights` でも外形セル方式より高い figure になる。総高さを固定したいなら `height` を指定する
- **`gap` は床である。** これは枠と枠の距離で、ラベルはその内側に住む (仕様6.3)。向かい合うマージンが `gap` より広い場所では、間隔がそれに合わせて広がる。閾値以下では `gap` は効かず、超えると効き始める

## 画面

左がエディタ、右がプレビュー。境界はドラッグで動かせる (ダブルクリックで既定に戻る)。コードは幅より高さを欲しがるので、エディタは下端の帯ではなく全高の列を取る。既定の分割位置は、プリセットが実寸で収まる幅をプレビューに残す。幅は記憶される。

`zoom` は `fit / 50% / 75% / 100% true size / 150% / 200%` で、既定は `fit`。実効パーセントは常に隣に表示され、100%でなくなった瞬間に琥珀色になる。線が太すぎないかを判断している人に78%で見せることはこのツールの意味を消すので、拡縮は決して黙って行われない。`fit` は縮小のみで、実寸を超えて拡大しない。パーセントにホバーすると、自然サイズ、使える領域、`fit` が選ぶ値が出る。

自然サイズは SVG が宣言している mm から取っており、レイアウト済みのボックスからは取らない。`#frame` は `#zoomer` の中にあり、その幅は前回の呼び出しが「自然サイズ×倍率」で設定した値なので、ボックスを測ると倍率が自分の入力に戻り、呼ぶたびに figure が縮んでいく。

## ブラウザ上での編集

エディタはコードの上にタブを並べたもの。`data`、パネルごとに1つ、最後に `layout`。

タブはファイルの*ビュー*であって、ファイルの一部を切り出したものではない。複数のパネルは普通同じ `panels.py` に住んでいるので、それらのタブは1つのバッファを共有し、タブはどこにスクロールするかだけを決める。タブごとにバッファを持つと、片方から保存したときにもう片方で打った内容を捨ててしまう。エディタはCDNから読む CodeMirror で、LSPも補完も無い。プレビューを見ながら軸範囲をちょっと直すためのものだからだ (仕様4, 7.1)。CDNに届かない場合は素のテキストエリアに落ちる。それでもファイルは編集できる。

保存は明示 (⌘S)。dev server はファイルを勝手に保存しない。保存するのはエディタである。

保存には特別扱いが無い。書き込みがディスクに落ち、watcher が気づき、接続している全プレビューが再描画する。ここでの編集と VS Code での編集は同じイベントである (仕様3.4)。これを真面目に受け取ると帰結が2つ出る。

- **書き込みは前提条件を持つ。** エディタは最後に読んだダイジェストを送る。ファイルが下で変わっていればサーバーは409を返し、バッファは保持される。打った内容を失うのは古いファイルより悪く、他人の編集を黙って上書きするのはその両方より悪い
- **パスは信用せず検証する。** `..`、絶対パス、プロジェクト外を指すシンボリックリンク、`.py` / `.toml` / `.svg` 以外は拒否する。サーバーは既定で localhost にバインドするが、`--host` で外に出せる

行は折り返す。プレビューの領域を残すために列を意図的に狭くしているので、普通のPythonの行では常に横スクロールが必要になってしまう。

`undo` は全文スナップショットを1つずつ遡る (仕様7.2 — テキストなのでこれ以上凝る必要はない)。スナップショットはサーバーのメモリ上にあり、**再起動すると消える**。

## 刷る前の確認

`check` はプレビューにフィルタをかける。グレースケールと、`feColorMatrix` による1型/2型/3型色覚のシミュレーション。「この2系列は色相しか違わない」を刷った後ではなく前に気づくためにある。行列は輝度を保存するので、この下で区別できているペアは、こちらが思っている理由で区別できている。

パネルのタブに切り替えると、そのパネルの軸枠がプレビュー上で縁取られる。プレビューは実寸描画なので、mm指定のオーバーレイがソルバの解いたボックスに正確に乗る。

## ライブリロード

ディスク上の `fig.toml` や `panels.py` を編集するとプレビューが更新される。VS Code での編集と、figalign が今後備える何かを通した編集は同じ経路を通る。watcher が唯一のトリガーで、ディスク上のファイルが唯一の真実の在り処だからだ。

変更は、実際に無効化する層に対応付けられる。

| 層 | キー | 無効化される条件 |
|---|---|---|
| データ | `load_data` のソース + そのファイルのモジュールスコープのソース | そのローダーか共通コードの編集、コード以外のファイルの変更 |
| 描画 | パネル関数のソース + 確定サイズ + データのキー | そのパネル1つの編集、またはサイズの変化 |
| 合成 | キャッシュしない | 毎リクエスト。数msなので |

なので `fig.toml` の `labels` を触ってもパネルは1枚も再描画されず、パネル関数を1つ編集すればそのパネルだけが再描画され、`gap` を変えると全サイズが動くので全部が再描画される。

パネルのモジュールはバイトコードキャッシュを経由せず直接コンパイルしている。`.pyc` はソースの mtime を**秒**解像度で記録し `(mtime, size)` で検証するので、同じ秒内でファイル長が変わらない編集 (ビン数や色の変更) は、さもなければ古いバイトコードから供給されてしまう。
